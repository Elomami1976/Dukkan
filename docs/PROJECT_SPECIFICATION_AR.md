# مواصفات مشروع Dukkan

## الرؤية

**Dukkan** تطبيق Desktop محلي Offline First لإدارة الأعمال الصغيرة، موجه بشكل أساسي إلى أصحاب الأنشطة في ليبيا. Windows هو النظام المستهدف للإصدار الأول. يجب أن تعمل الوظائف الأساسية دون اتصال دائم بالإنترنت ودون حساب أو خدمة سحابية.

قاعدة المشروع: لا تعتمد الوظائف الأساسية على Cloud Services، وتحفظ كل البيانات الأساسية محلياً على جهاز المستخدم.

## التقنيات والمعمارية

التقنيات المخطط لها:

- Tauri
- React
- TypeScript
- Rust
- SQLite
- Tailwind CSS
- Zustand
- React Hook Form
- Zod
- Recharts

المعمارية:

```text
React UI
  -> Tauri Commands
    -> Rust Services
      -> SQLite
```

لا تتعامل React مباشرة مع SQLite. تفصل الواجهة عن منطق الأعمال وعن الوصول إلى قاعدة البيانات، مع migrations وقيود Foreign Keys وفهارس مناسبة.

## المميزات الرئيسية

- إعداد النشاط لأول مرة وتخصيص اسم النشاط والشعار والألوان.
- تسجيل الدخول، مع أدوار `Admin` و`Cashier` قابلة للتوسعة.
- Dashboard عربية.
- إدارة المنتجات والتصنيفات والوحدات وProduct Variants وBarcode.
- نقطة بيع POS للمبيعات النقدية والآجلة وMixed Payments.
- إدارة العملاء وديون العملاء وكشوف الحساب والدفعات.
- إدارة الموردين والمشتريات ودفعات الموردين.
- مرتجعات البيع ومرتجعات الشراء.
- المخزون وحركة المخزون وتنبيهات انخفاض المخزون.
- المصروفات والتقارير والأرباح والفواتير.
- طباعة Thermal 80mm وA4.
- النسخ الاحتياطي والاسترجاع محلياً والمرفقات المحلية.
- دعم العربية وRTL.
- إدخال المبالغ بالأرقام أو الكلمات العربية.
- دليل استخدام داخل التطبيق يعمل بدون إنترنت.

## سلامة الأموال

- العملة الافتراضية هي `LYD`.
- `1 LYD = 1000 dirhams`.
- لا تستخدم `FLOAT` للأموال.
- تخزن الأموال كـ `INTEGER minor units`.
- المثال: `12.500 LYD = 12500`.

يجب أن يكون `MoneyInput` قادراً على قبول:

```text
5250
5,250
5250.500
خمسة آلاف ومئتان وخمسون
```

ثم يحوّل القيمة إلى رقم مؤكد بعد `Parse` و`Validate` و`Normalize` وقبل الحفظ. إذا كان النص العربي غامضاً، لا يتم التخمين ويطلب النظام من المستخدم كتابة قيمة أوضح.

## المخزون والعمليات المالية

لا يعدّل المخزون مباشرة دون تسجيل `Inventory Transaction` تحتوي المنتج والكمية قبل وبعد ونوع الحركة والمرجع والمستخدم والتاريخ.

العمليات المالية المهمة يجب أن تتم داخل `Database Transaction` واحدة مع `Rollback` عند الفشل، ومنها المبيعات والمشتريات والمرتجعات والدفعات وتسويات المخزون والإعداد الأولي.

لا تحذف البيانات التاريخية عشوائياً. تستخدم `is_active` للمنتجات والعملاء والموردين عند الحاجة، وتستخدم الفواتير حالات مثل `completed` و`cancelled` و`returned`. عند البيع تحفظ تكلفة المنتج وقت البيع داخل `sale_items` حتى لا تتغير الأرباح التاريخية عند تغيير سعر الشراء لاحقاً.

## مراحل التنفيذ

المشروع حالياً في مرحلة التطوير. لا ينشر إصدار `v1.0.0` ولا ينشأ GitHub Release بهذا الاسم قبل اكتمال التطبيق واختباره وبناء Windows Installer واختبار التشغيل دون إنترنت والنسخ الاحتياطي والاسترجاع.

## التشغيل والجودة

كل ميزة ظاهرة للمستخدم يجب أن تكون موصولة بوظيفة حقيقية، لا Placeholder أو زر وهمي. يجب الحفاظ على TypeScript strict، وإضافة اختبارات مناسبة للحسابات المالية والمخزون والصلاحيات وعمليات البيع والشراء والنسخ الاحتياطي. تراجع روابط Markdown واسم المشروع Dukkan ودعم العربية وRTL قبل كل إصدار.
